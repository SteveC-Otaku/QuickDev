# Quick Dev 1.0.2 · Windows Uvicorn 热重载兼容

日期：2026-10-12。正式发布 v1.0.2，提供 x64 / ARM64 安装包与签名更新清单。官网构建产物随版本生成；OSS 部署由七七另行上传，不代表网站已经上线。

## 自动兼容

Quick Dev 启动服务时给其进程树加入仅该次启动生效的 Python 兼容目录。Windows 下识别 `python -m uvicorn … --reload` 和标准 `uvicorn.exe … --reload` 后，自动将后端放入独立隐藏控制台，避免一体脚本中的重载 Ctrl+C 串扰 npm。包括带这些标准入口的 npm、PowerShell 或 CMD 启动脚本，无需修改项目脚本。

保持虚拟环境、原 PYTHONPATH、原 sitecustomize、实时日志和进程树关系；新控制台进程不使用 Job 的 BREAKAWAY 标志，软件停止仍通过 Job 回收全部受管进程。重定向日志时，将 Uvicorn 的控制台唤醒写入同时送到独立 CONOUT$，避免重载等待卡住。

兼容代码内嵌在应用中，在本地 QuickDev/runtime 下按内容生成缓存，不安装项目依赖，不改项目文件、注册表或全局 Python 设置。普通 Python 命令不转启动入口；Node/Vite 不执行这段 Python 代码。

## 范围

- 当前保护标准 Uvicorn CLI 的 Windows 热重载；环境变量 UVICORN_RELOAD 启用的标准入口也可识别。
- 不承诺保护 `uvicorn.run()` 程序内调用、自定义重载器、`python -S`/`-I` 禁用 site/PYTHONPATH、启动脚本主动覆盖 PYTHONPATH 的场景。
- 支持进程环境 QUICKDEV_DISABLE_RELOAD_GUARD=1 跳过自动重启包装，供兼容排查使用。运行中的旧服务不会自动切换。
- 多服务项目仍推荐用 Quick Dev 的独立服务和启动方案；当前修复为常见的一体脚本提供兜底，不能识别所有任意脚本的内部执行结构。

## 验证

实际 Windows 隔离回归覆盖 PowerShell、CMD、uvicorn.exe 三组旧式共享控制台脚本，每组连续三次真实 Uvicorn 热重载。验证临时 npm 前端保持可访问、后端 PID 更新、原 sitecustomize 生效、中文日志可见、新后端属于同一 Job，TerminateJobObject 后前后端端口释放。

Rust 回归覆盖兼容缓存写入、复用及篡改拒绝，以及受管 Shell 与后代的 Job 停止。既有 npm 回归与前端检查继续执行。没有启动、停止或重启真实项目，没有业务数据读写；不是已安装软件的原生 UI 验收。

最终回归使用 stdout/stderr 管道捕获日志，与 Quick Dev 的实际日志捕获方式一致；另验证普通 Python 初始化、中文输出、退出码 23 和 Windows 状态码 0xC0000005 的原样传递。多服务并发准备兼容缓存时使用进程内互斥锁，避免相同临时文件竞争。

回归入口（Python 环境需已有 Uvicorn，Node/npm 需在 PATH）：

```powershell
python scripts/test-python-reload.py --python "C:\path\to\venv\Scripts\python.exe"
```

发布复测：全部 53 项原生测试通过，`npm test` 通过，Svelte 检查 0 错误 / 0 警告。真实热重载三组各三次通过，复测证据保存在 `_tasks/2026-10-12-release-1.0.2/reload/evidence.json`。

正式文件：`release/dist/v1.0.2/github/`；完整官网部署目录：`release/dist/v1.0.2/oss/`。两种架构的更新器签名以应用内置公钥验证，SHA256SUMS.txt 随 GitHub 资产一起提供。ARM64 仅做交叉构建和文件校验，没有 ARM 设备运行验收；本轮没有安装覆盖现有软件或进行原生 UI 手动点击验收。
